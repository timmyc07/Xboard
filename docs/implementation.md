# Xboard implementation

## Scope and sources

- Foundation: https://github.com/Kelsiito/clipboard (MIT; provenance retained in Git and LICENSE).
- Reference: https://github.com/p0deje/Maccy — pasteboard polling and ignored types.
- Clipboard conventions: https://nspasteboard.org/ — ConcealedType, TransientType, AutoGeneratedType and source markers.
- UI reference: https://github.com/momenbasel/pesty. No code from Pesty is included.

## Native stack

Swift (Swift 5 language mode), SwiftUI, AppKit, Carbon global hotkey registration, CryptoKit AES-GCM, the local macOS login Keychain, LocalAuthentication, CoreGraphics synthetic paste, ServiceManagement login item, Vision OCR, XCTest. No third-party runtime package or backend.

The product is Xboard (`io.github.timmyc07.Xboard`). Storage and Keychain identity are separate from the upstream app. The only active default global shortcut is ⌥V. Optional capture and stack shortcuts must be configured by the user.

## Core flow

PasteboardMonitor reads changeCount on the common run loop and only captures changed content. It excludes concealed/transient/autogenerated snapshots, ignored apps, paused capture, and its own recent paste-back window. A second changeCount check rejects snapshots torn across two copy operations.

ClipboardStore deduplicates captures and preserves pinned status and identity. Configured limits count only unpinned items; pins survive limit changes, capture, reload, and retention cleanup. Newest items appear first within each group. Data is encrypted atomically and existing files are preserved on decryption/key failures.

ClipboardPanelController remembers the destination before opening the picker. Search and filtering update selection, the selected row is highlighted, and keyboard navigation scrolls into view. A selected item restores its original supported representations. AppState activates the remembered destination; synthetic paste occurs only if Accessibility is granted, focus still belongs to that destination, and the pasteboard has not changed. Otherwise the user can paste manually.

## Settings and permissions

All preferences are in the app. New installs open Settings. Clipboard read consent is handled by macOS. Accessibility is optional: the picker displays an explicit enable action when access is missing, and Settings exposes the same action. Clicking it requests the macOS permission prompt and opens the Accessibility pane. The user grants access; capture and manual paste remain available without it. Screen Recording is requested only by optional capture/recording tools. Login at startup is opt-in.

Interface language follows [macOS language preferences](https://developer.apple.com/localization/) through the native String Catalog and Bundle localization selection. English is the development language and fallback; Traditional Chinese is also supported. Regional preferences such as `en-US` and `zh-Hant-TW` resolve to the corresponding supported language. macOS per-app language preferences are respected. Relaunch Xboard after changing language preferences.

## Acceptance checks

- Compile and XCTest on the installed Xcode/macOS.
- Default ⌥V; no automatic global Command-G binding.
- More than three pins persist and survive a lowered limit and subsequent captures.
- Encrypted reload, authentication/tamper failure, dedupe, search, images/files.
- Traditional Chinese catalog compiled into the app.
- Visible keyboard selection and safe focus/manual paste behavior.

Manual checks on other macOS versions, Intel hardware, alternate input methods, protected password fields, and Developer ID/notarization must be reported separately. No production signing credentials are stored in this repository.

Local builds intentionally use the macOS file-based login Keychain through SecItem, with synchronization disabled. The data protection Keychain requires a provisioned keychain access group and returned errSecMissingEntitlement (-34018) with ad-hoc signing. There is one backend, with no insecure key-file fallback. The native Keychain round-trip test creates and removes only a uniquely named synthetic test key.

Keychain access is preloaded on a background queue before restoring persistent stores, so an authorization dialog cannot block app startup. Capture remains available in memory while access is pending or denied. Retrying access merges pending captures with saved data and preserves saved pins; after a successful load, retrying a failed write saves the current in-memory state without resurrecting deleted records. Tests cover these recovery paths.
